# Security policy

## Supported versions

Security fixes target the current `main` branch and the most recent supported
release. Older snapshots may receive a fix when maintainers judge a backport
practical.

## Reporting a vulnerability

Use the repository's private GitHub Security Advisory reporting feature when it
is available. If private reporting is unavailable, contact a maintainer
privately and disclose only enough in public to establish contact. Do not place
exploit details, credentials, private server information or an unpatched
vulnerability in a public issue.

Include:

- affected revision and platform;
- a concise impact statement;
- reproducible steps or a minimal proof of concept;
- relevant logs without secrets; and
- any suggested mitigation.

Maintainers should acknowledge a report promptly, keep the reporter informed,
coordinate a proportionate disclosure date and credit the reporter if desired.
No bounty or response-time guarantee is implied.

## Disclosure and licensing

A short embargo may protect users while a fix is prepared. The fix and related
project-owned material are then published under the repository's normal
licences. Security coordination does not create a proprietary exception.
